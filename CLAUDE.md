# Almaty Traffic Lab: правила для агентов

Ты работаешь над одной задачей из `docs/tasks/T-NN-*.md` в отдельном окне. Прочитай этот файл целиком,
затем карточку задачи, затем только те документы, на которые она ссылается. Не читай весь репозиторий подряд.

## Что это за проект
Интерактивная 3D-микросимуляция движения в центре Алматы (браузер, Three.js + TypeScript) с детекцией
и объяснением узких мест. Цель: показать, что симуляция учитывает нюансы движения (скорости, число полос,
левые карманы, доп. секции светофоров, автобусные выделенки, пешеходы, слияния, блокировка перекрёстков,
навигаторные перестроения маршрутов). Данные условные (OSM + генератор допущений), ручных данных нет.
Подробности: `docs/PLAN.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`.

## Пакеты
| Пакет | Роль | Ограничения |
|---|---|---|
| `packages/contracts` | Схемы (zod) и типы: сеть, конфиг, сценарии, причины, метрики, буферы, протокол воркера | **Заморожен.** Меняется только через решение владельца (см. ниже) |
| `packages/map-data` | Импорт OSM плитками, компилятор OSM → `network.json`, генератор допущений, применение overrides | Node-скрипты, детерминированный вывод |
| `packages/sim-core` | Чистая симуляция: IDM + MOBIL, светофоры, перекрёстки, маршрутизация, автобусы, пешеходы, метрики, детектор | Без DOM, Three, таймеров, `Math.random`, `Date.now` |
| `packages/sim-worker` | Web Worker вокруг sim-core, протокол сообщений, пинг-понг буферов, клиент для главного потока | Только протокол из contracts |
| `apps/web` | Three.js рендер + React UI | Ничего не считает сам, только читает буферы и метрики |

## Команды
```bash
pnpm check                 # typecheck + lint + determinism + tests. Definition of Done каждой задачи
pnpm test:watch            # vitest в watch-режиме
pnpm format                # Biome
pnpm run import --bbox small   # OSM → data/osm/<bboxId>/ (T-01); именно `run`: `pnpm import` — встроенная команда pnpm
pnpm run compile --bbox small  # snapshot → data/networks/<bboxId>.network.json.gz (T-02+)
pnpm sim --network ... --minutes 10 --seed 1   # headless-раннер (T-20)
pnpm dev                   # Vite dev server
```
Node 22 (нативная загрузка `.ts`, импорты с расширением `.ts`), pnpm 10, TypeScript strict, Vitest, Biome.

## Железные правила
1. **Контракты заморожены.** Если задача не решается без изменения `packages/contracts`, не меняй их.
   Заверши всё, что можно, и в отчёте напиши раздел «Требуется решение» с предложением изменения и причиной.
   Исключение: добавление новой **опциональной** секции/поля с default, если карточка это явно разрешает.
2. **Детерминизм.** В `sim-core` и `contracts` запрещены `Math.random`, `Date.now`, `performance.now`, `new Date`
   (проверяется `scripts/check-determinism.mjs`). Случайность только через `Rng` из `sim-core/src/rng.ts`,
   сиды и `fork()`. Итерация только по массивам в фиксированном порядке. Один сид + одна сеть + один сценарий
   = побитово одинаковые траектории.
3. **Ядро без окружения.** `sim-core` не знает о DOM, Three, воркерах и файловой системе (кроме CLI-файла).
4. **Горячие циклы на SoA.** Состояние машин в типизированных массивах (`Float32Array`, `Uint8Array`, ...),
   без аллокаций внутри `step()`, без замыканий и `Map` в цикле по машинам. Читаемость важнее микрооптимизаций,
   но структура данных задаётся один раз и не меняется.
5. **Происхождение атрибутов.** Всё, что компилятор придумал сам, помечается `provenance: { attr: "default" }`.
   Всё, что взято из OSM, `"osm"`. Никаких тихих допущений.
6. **Единственная точка входа симуляции** — интерфейс `Simulation` из `sim-core/src/simulation.ts`.
   Воркер, CLI и тесты используют только его.
7. **Язык.** Код, идентификаторы, комментарии, коммиты: английский. Документация, карточки, отчёты, строки UI: русский.
   Строки UI держи в одном модуле (`apps/web/src/i18n/ru.ts`), чтобы позже добавить казахский.
8. **Стиль.** Biome, `strict`, без `any`, без `!` (non-null assertion), без `// @ts-ignore`. Импорты внутри пакета
   с расширением `.ts`. Между пакетами только через `@atl/<name>`.
9. **Тесты.** Каждая задача добавляет тесты, а не только код. Тесты нюансов лежат в `packages/sim-core/test/nuances/`;
   закрывая нюанс, меняй `it.todo` на `it` и реализуй проверку по `docs/NUANCES.md`. Не удаляй и не переформулируй
   чужие `todo`.
10. **Не расширяй объём.** Делай ровно то, что в карточке. Идеи для соседних задач записывай в отчёт.

## Как взять задачу
1. Открой `docs/tasks/T-NN-*.md`. Проверь, что все зависимости из шапки уже в `main` (`git log --oneline | grep T-`).
2. Работай в своём worktree и ветке. Если окно запущено из чипа задачи, worktree уже создан за тебя:
   проверь `git worktree list` и `git branch --show-current`; если ветка не `task/T-NN`, выполни
   `git switch -c task/T-NN`. Иначе создай worktree сам:
   ```bash
   git worktree add ../atl-T-NN -b task/T-NN main
   cd ../atl-T-NN && pnpm install
   ```
   В любом случае первым делом `pnpm install` и убедись, что `pnpm check` зелёный до твоих правок.
3. Реализуй по карточке. Запускай `pnpm check` часто. Синтетические сети для тестов: `packages/sim-core/test/fixtures/builders.ts`.
4. Definition of Done: `pnpm check` зелёный, критерии приёмки из карточки выполнены, README пакета обновлён,
   коммиты по Conventional Commits с префиксом задачи: `feat(sim-core): T-04 IDM kernel`.
5. Запушь ветку и открой PR в приватный репозиторий: `git push -u origin task/T-NN`, затем
   `gh pr create --base main --fill`. Слияние в `main` делает владелец после ревью.
6. Заверши отчётом в чате по шаблону ниже.

## Координаты и единицы
Локальная метрическая система: x = восток, y = север, метры от центра bbox (`meta.origin`).
В Three.js: `position.set(x, height, -y)`, ось Y вверх. Скорости в м/с внутри, км/ч только в UI.
Время симуляции в секундах, время суток в минутах от полуночи. Углы в радианах против часовой стрелки от +x.

## Глоссарий
- **Link**: одно направление улицы между узлами. **Lane**: полоса внутри link, `index 0` = крайняя левая.
- **Pocket (карман)**: полоса с `startS > 0`, открывается перед перекрёстком.
- **Connector**: движение полоса → полоса через узел; **conflict point**: точка пересечения двух connectors.
- **Signal group**: сигнал для набора движений; **arrow section (доп. секция)**: группа `section: arrow_left|arrow_right`.
- **Binding constraint (связывающее ограничение)**: причина, по которой машина не едет быстрее (см. `contracts/src/causes.ts`).
- **Root cause**: причина головы очереди, унаследованная всеми, кто стоит за ней.
- **Gate**: узел на границе bbox, источник/сток машин. **Attractor**: точка притяжения внутри.
- **Segment**: отрезок полосы 25 м для метрик и тепловой карты.
