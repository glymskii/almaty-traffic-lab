# T-09. Светофоры в рантайме

**Пакет:** `packages/sim-core` · **Волна:** 2 · **Уровень:** M · **Размер:** ~600 строк · **Зависит от:** T-04, T-03 · **Разблокирует:** T-11

## Цель
Автомат состояний контроллеров и групп, стоп-линии как виртуальные препятствия IDM, поведение на жёлтом,
погашенные стрелки. Состояния групп попадают в `FrameBuffers.signalStates`. Закрывает N05, N06.

## Контекст
`docs/ARCHITECTURE.md` («Светофоры», «Порядок шага» п.1 и п.6); `packages/contracts/src/{state,sim-config}.ts`
(`SignalState`, `SignalTiming`); `docs/NUANCES.md` N05, N06; `crossroads` из T-03.

## Что сделать
1. `runtime/signals.ts`: для каждого контроллера предвычислить таблицу «время в цикле → состояние каждой группы»
   с шагом `dtS` (память: цикл/dt × групп байт, приемлемо), учесть `offsetS`, `flashingGreenS`, `redYellowS`;
   `arrow_*` группы вне зелёного `OFF`. `stateAt(groupIdx, simTimeS)`.
2. Для каждой полосы, чей выход сигнализирован: виртуальный лидер на стоп-линии (`s = endS`), когда для нужного
   коннектора состояние не в `{GREEN, FLASHING_GREEN, YELLOW-проезд}`. Правило жёлтого: если машина не может
   остановиться с замедлением ≤ `comfortDecel·1.5` до стоп-линии — проезжает; иначе тормозит. `RED_YELLOW` = стоп.
3. Причины: `signal_red` при остановке у стоп-линии; `arrow_off` — левый коннектор, чья группа `arrow_left` погашена,
   пока основная группа подхода зелёная (машина в кармане стоит, соседняя сквозная едет).
4. Машина «выбирает коннектор» уже в T-04 (первый разрешённый); здесь проверка состояния именно этого коннектора.
5. Кадр: `signalStates` заполняется по глобальному порядку групп.
6. Тесты: таблица состояний для 2-фазного плана (N06, включая `OFF` для стрелок); N05 на `crossroads` со сквозным потоком
   (очередь на красном, разгрузка ≈ 1800 веh/ч/полосу ±15%); жёлтый: машина в 5 м от стоп-линии на 50 км/ч проезжает,
   в 60 м — останавливается; `offsetS` сдвигает таблицу.

## Заметки от T-04 (учесть)
- Виртуальный лидер ставится на `trackEndS` полосы при красном; коннектор для проверки уже выбран в `nextTrack[i]` (см. README sim-core).
- `signalStates` в кадре пока заполняются `OFF`; заменить на реальные состояния.

## Заметки из ревью T-04 (учесть)
- В `RuntimeNetwork` нет индексов `connector.signalGroupId` и `protection` (есть только плоский `signalGroupIds` для кадров): добавить `connSignalGroup`/`connProtection` (Int32Array/Uint8Array по трекам).
- Стоп-линия реализуется как «виртуальное препятствие» в паттерне «минимум по препятствиям» (после правок T-04 в `computeAccelerations` есть `accelTowardObstacle`); не переписывать блок, а добавить препятствие.
- В `crossroads({cycleS})` это бюджет зелёного, полный цикл считать через `cycleLengthS(controller)`.

## Заметки после ревью (интеграция 8 сентября 2026)
Слито в `main` без правок кода — реализация проверена построчно против `docs/ARCHITECTURE.md` («Светофоры»,
«Порядок шага» п.1/п.6) и карточки, `packages/contracts` не тронут, `pnpm check` зелёный (typecheck, lint,
determinism, 240 passed / 27 todo на объединённом `main`, включая T-07). Что именно проверено:
- Таблица состояний (`SignalRuntime`) даёт ровно последовательность GREEN → FLASHING_GREEN(`flashingGreenS`) →
  YELLOW(`phase.yellowS`) → RED → RED_YELLOW(`redYellowS`) → GREEN для `main`-групп и GREEN → FLASHING_GREEN → OFF
  (без YELLOW/RED_YELLOW/RED) для `arrow_*`; `offsetS` — сдвиг начала цикла (`tIn = simTimeS − offsetS`), что совпадает
  с описанием поля в `packages/contracts/src/network.ts` («shift of the cycle start relative to global time 0»).
- Дилемма жёлтого (`mustStopAtYellow`) арифметически верна и даёт заявленный в карточке результат на дефолтных
  водительских параметрах (5 м/50 км/ч — проезд, 60 м/50 км/ч — торможение); юнит-тест на уровне ядра это фиксирует.
- `connSignalGroup`/`connProtection`/`groupIsArrow`/`signalGroupIndex` в `RuntimeNetwork` заведены по треку/глобальному
  индексу группы ровно так, как просила заметка ревью T-04; несигнализированные коннекторы (`connSignalGroup < 0`)
  не трогаются — свободны для T-11.
- Пешеходные группы (`kind: "pedestrian"`) не выделены отдельно и участвуют в общем автомате `main` — это осознанное
  решение исполнителя (см. его заметку к T-15 ниже), а не пропуск: секция `section` по умолчанию `"main"`, поэтому
  автомат зелёный/жёлтый/красный работает и для них без изменений.
- Побочная правка при интеграции: `docs/NUANCES.md` — статусы N05/N06 были обновлены на `зелёный`, а сводный абзац
  статуса (число `it.todo`, было посчитано под волну 1) пересчитан под актуальный `pnpm test` (240 passed / 27 todo).
  Сам код T-09 правок не потребовал.
- Не проверялось за пределами существующих тестов: поведение на контроллере с одной группой в нескольких
  пересекающихся фазах (не встречается в текущих билдерах) и `pedestrianPhase: false` (поле не используется T-09,
  предположительно относится к T-08/T-15).
