# T-04. Ядро симуляции: SoA, IDM, спавн, детерминизм

**Пакет:** `packages/sim-core` · **Волна:** 1 · **Уровень:** S · **Размер:** ~1200 строк · **Зависит от:** — · **Разблокирует:** T-06 (интеграция), T-09, T-10, T-12

## Цель
Реализовать `createSimulation` и интерфейс `Simulation` для движения по полосам без перестроений и перекрёстков:
загрузка `Network` в плоские структуры, пул машин на типизированных массивах, IDM, простой спавн на воротах,
кадры, хеш траекторий, статистика поездок. На `straightRoad` уже должны проходить N01, N03, N04, N25.

## Контекст
`CLAUDE.md` (правила 2–4, 6); `docs/ARCHITECTURE.md` («Сеть в рантайме», «Машины: SoA», «Порядок шага», «Детерминизм»);
`packages/sim-core/src/{simulation,rng}.ts`; `packages/contracts/src/{state,sim-config,metrics,causes}.ts`;
`docs/NUANCES.md` N01–N04, N25.

## Контракты
Реализует `Simulation` целиком по сигнатуре (методы, которые появятся позже, возвращают честные заглушки:
`writeMetrics` — нули, `report` — пустой отчёт с `totals`). Не меняет `contracts`.

## Что сделать
1. `runtime/network.ts`: индексация `Network` → массивы узлов/линков/полос/коннекторов (int-индексы), таблицы
   соседей полос слева/справа с учётом `startS/endS`, коннекторы на выходе полосы, кумулятивные длины полилиний
   для перевода `s → (x, y, heading)`. Сегменты метрик (`SegmentDescriptor[]`) по `metrics.segmentLengthM`.
2. `runtime/vehicles.ts`: пул ёмкостью `demand.vehicleBudget`, SoA-массивы (см. ARCHITECTURE), список свободных слотов,
   упорядоченные по `s` списки машин на полосу (массив индексов + сортировка вставкой при движении).
3. `models/idm.ts`: чистая функция ускорения IDM (`v0, T, s0, a, b, δ=4`) с тестами на известные значения;
   `models/driver.ts`: сэмплирование параметров водителя из `config.driver` и класса.
4. `step()`: порядок из ARCHITECTURE (для этой задачи: сигналы и прочее — пусто), лидер = следующий в списке полосы,
   свободный поток ограничен `v0`, интеграция полунеявным Эйлером, `cause` = `free_flow | speed_limit | leader`.
   Переход с полосы на следующую: в этой задаче машина, доехавшая до конца линка, выбирает первый разрешённый
   коннектор (или исчезает на воротах) и проходит его как короткую полосу; конфликты игнорируются (T-11).
5. Спавн: на каждых воротах пуассоновский процесс с интенсивностью
   `tripsPerHourPeak · hourlyProfile[h] · multiplier · weightIn / Σ weightIn`; при `tripsPerHourPeak = 0` —
   авто-оценка `0.7 × Σ(ёмкость входящих полос)`. Появление только если в начале полосы есть зазор; иначе `spawn_wait`
   в счётчике ожидания. Класс: `car`/`taxi` по `taxiShare`. Удаление на воротах выхода.
6. `writeFrame`, `signalGroupIds`/`crosswalkIds` (порядок из сети), `setParams` с проверкой `RUNTIME_SAFE_PARAM_PATHS`,
   `trajectoryHash` (FNV-1a по округлённым до 0,01 x, y, v в порядке слотов, фолдинг на каждом шаге),
   `tripStats()` (см. интерфейс).
7. Часы: `simTimeS`, `timeOfDayMin = startTimeMin + simTimeS/60` (mod 1440).
8. Тесты: IDM по формуле; N01, N03, N04, N25; «на прямой дороге при малом спросе машины не сталкиваются»
   (зазор ≥ s0 всегда); производительность ориентировочно: 5000 машин на `straightRoad({lengthM: 5000, lanes: 3})` шаг < 5 мс.
