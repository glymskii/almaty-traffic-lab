# T-25. Тепловая карта и панель узких мест

**Пакет:** `apps/web` · **Волна:** 5 · **Уровень:** M · **Размер:** ~1000 строк · **Зависит от:** T-19, T-23 · **Разблокирует:** T-26

## Цель
Окраска полотна по скорости из `MetricsFrame`, список Топ-N с причинами и рекомендациями, маркеры над узкими
местами, подлёт камеры, спарклайн задержки, миникарта.

## Контекст
`packages/contracts/src/metrics.ts` (`MetricsFrame`, `BottleneckReport`, `SegmentDescriptor`); T-05 (геометрия полос,
камера `focus`); T-19 (`recommendations.overrides`); `docs/DECISIONS.md` D11, D13; палитра: зелёный → жёлтый → красный
приглушённые, читаемые на сером полотне; при `speedRatio` без данных — серый.

## Что сделать
1. `scene/heatmap.ts`: атрибут цвета на геометрии сегментов (T-05 строит полосы; разбить ленты по сегментам 25 м или
   добавить отдельную геометрию сегментов поверх полотна). Режимы: «сейчас» (последний семпл — из кадра: средняя скорость
   машин на сегменте считается в воркере? Нет: использовать `speedRatio` окна и отдельный короткий режим не делать; режимы
   «окно 5 мин» и «выкл»). Легенда цветов.
2. Вкладка «Узкие места»: таблица Топ-N (ранг, название, задержка маш-ч/чел-ч, переключатель сортировки, LOS-бейдж, V/C),
   раскрытие строки: полоса долей причин с подписями `CAUSES.ru`, рекомендации кнопками «Применить в сценарии» (создаёт
   override через T-24 API) и «Показать».
3. Маркеры: CSS2D над `focus` с номером ранга и цветом по LOS; клик = выбор строки + `camera.focus`.
4. Спарклайн суммарной задержки за последние 30 минут (canvas 2D, без библиотек) и число активных узких мест.
5. Миникарта: canvas 2D с линками, окрашенными по `speedRatio`, прямоугольник видимой области, клик = перелёт.
6. Тесты: маппинг `speedRatio → цвет`, сортировка/фильтрация отчёта, спарклайн-буфер.

## Файлы
`apps/web/src/scene/{heatmap,markers}.ts`, `src/ui/{BottlenecksTab,CauseBar,Sparkline,Minimap}.tsx`, тесты.

## Заметки от T-18 (учесть)
- **`delayVehS`/`delayPersonS` в кадре пилят на ±6% с периодом `windowS / 8`** (37,5 с при дефолтах):
  окно — кольцо из 8 слотов, вытесняется слот целиком, а `frame.windowS` всегда отдаёт номинальные 300 с.
  Замер и разбор — раздел «Заметки после ревью» в карточке T-18. Не показывайте абсолютную задержку без
  сглаживания: число заметно прыгает раз в 37,5 с. Доли и средние (`speedRatio`, `density`, `flow`,
  `queueM`, `congestedShare`, `causeShare`, `vcRatio`) от этого не страдают — их можно рисовать как есть.
- **Остановок в `MetricsFrame` нет** (контракты заморожены). Если тепловая карта захочет остановки —
  они лежат в `kernelOf(sim).metricsWindow.stopsInWindow(segment)`, то есть доступны только в процессе
  симуляции, а не через кадр в воркере. Пробрасывать придётся отдельным каналом.
- **`totals.meanSpeedKph` смещена вверх в заторе** (считается по завершившимся поездкам). На панели
  показывайте её вместе со `stoppedShare` и `congestedSegmentShare`.

## Заметки от T-19 (интеграция детектора в main, учесть)
- **`report().items` теперь настоящие.** До `metrics.topN` элементов, порядок всегда по машино-часам
  (`delayVehH`); сортировку «по людям» делай на клиенте по `delayPersonH` — это решение карточки T-19,
  а не недоделка.
- **`item.segmentIndices`** — индексы в порядке `segments()`, годятся для подсветки прямо в геометрии
  сегментов. **`item.focus`** — координата стоп-линии подхода (для «середины линка» — середина участка),
  в локальных метрах; для Three.js `position.set(focus[0], h, -focus[1])`.
- **`item.title` уже собран по-русски** («проспект Абая × улица Наурызбай Батыра, подход с севера»,
  «улица Абая, участок»); при отсутствии имени узла подставляется имя линка, затем id. Строки UI вокруг
  него (заголовки панели, подписи причин, названия сценариев рекомендаций) держи в
  `apps/web/src/i18n/ru.ts` — в отчёт их не тащить.
- **Не показывай `los` в одиночку.** `los = losFromVc(vcRatio)`, а `vcRatio` считается по реализованному
  потоку: запертый подход пропускает мало машин, поэтому V/C мал, поэтому LOS высокий. Замер на
  `almaty-abay-small`: элемент #1 — `queueM` 95 м, `speedRatio` 0.00, `persistence` 1.00 и `los` **A**;
  #4 — 133 м и снова **A**. «LOS A» рядом со 133 м очереди читается как ошибка панели. Показывай `los`
  только вместе с `queueM`, `speedRatio` и V/C, либо не показывай вовсе (решение владельца, разбор —
  «Заметки после ревью» в карточке T-19).
- **`recommendations` бывает пустым, и это штатно.** Причина без строки в таблице
  (`lane_change_wait`, `bus_dwell`, `yield_priority`, `spawn_wait`), нерегулируемый узел (светофоры есть
  только у 70 узлов из 444 на малой сети) или незакрытый порог V/C оставляют элемент без единого
  сценария — на реальной сети это примерно половина топ-6. Верстай пустое состояние явно, а не
  предполагай, что кнопка «применить» есть всегда.
- **`causes` — топ-5 долей, сумма ≈ 1** по `DELAY_CAUSE_KEYS` (нормировка идёт по ним же, не по всем
  причинам). Доли устойчивы, в отличие от абсолютной задержки: `delayVehH`/`delayPersonH` наследуют
  пилу ±6 % с периодом `windowS / 8` из T-18 — их сглаживай.
