# T-13. Рендер машин, светофоров и пешеходов

**Пакет:** `apps/web` · **Волна:** 2 · **Уровень:** M · **Размер:** ~800 строк · **Зависит от:** T-05, T-06 · **Разблокирует:** T-23

## Цель
Из `FrameBuffers` рисовать машины инстансами с интерполяцией между кадрами, стоп-сигналами и поворотниками;
светофорные головки с состояниями секций; пешеходов точками на зебрах. Это веха M1/M2 визуально.

## Контекст
`packages/contracts/src/state.ts` (`FrameBuffers`, `VehicleFlag`, `SignalState`, коды классов);
`packages/sim-worker` (`createSimClient`, `createStubSimulation`); T-05 сцена; `docs/DECISIONS.md` D13.

## Что сделать
1. `scene/vehicles.ts`: `InstancedMesh` на класс (легковая: два бокса «кузов+кабина», автобус: длинный бокс, троллейбус:
   бокс + две штанги, такси: легковая жёлтая). Ёмкость = `vehicleCapacity` из `ready`. Цвет через `instanceColor`
   (палитра легковых из 6 приглушённых цветов по `id % 6`). Стоп-сигналы: маленький красный инстанс сзади при `BRAKING`;
   поворотники мигают 2 Гц при `BLINKER_*`. Скрытие неиспользуемых инстансов масштабом 0.
2. Интерполяция: хранить два последних кадра, по `id` строить карту слот→позиция (Map допустим на главном потоке, но
   лучше `Int32Array` по `id`, если `id` ограничен ёмкостью: `id = slot + generation·capacity`, взять `id % capacity`);
   позиция = lerp по времени между кадрами, heading через кратчайший угол.
3. `scene/signals.ts`: для каждой сигнальной группы столб + головка у стоп-линии подхода (позиция: конец первой полосы
   группы, смещение вправо на 2 м); основная секция: три лампы; `arrow_left/right`: дополнительная лампа со стрелкой сбоку.
   Цвета по `SignalState`, мигание для `FLASHING_GREEN`, `OFF` = тёмная. Инстансы ламп, обновление цвета из `signalStates`.
4. `scene/pedestrians.ts`: по `crosswalkPeds[i]` рисовать `n` точек, равномерно вдоль зебры (инстансы сфер r=0,3).
5. Подключить `SimClient` в приложении: `init` с сетью (демо-сеть или загруженная), `runUntil` прогрева с прогресс-баром,
   `play(1)`; на `onFrame` обновлять инстансы. Пока нет T-04 в `main`, использовать `createStubSimulation` через флаг.
6. Тесты: интерполяция углов и позиций; раскладка цветов; сборка головки светофора для группы.

## Файлы
`apps/web/src/scene/{vehicles,signals,pedestrians,interpolation}.ts`, `src/sim/client.ts`, тесты.

## Критерии приёмки
- [ ] 20 000 инстансов при 60 fps на этой машине (стресс-режим со стабом) — `?stress=1` рендерит без ошибок
  (см. заметки после ревью), но fps инструментально не замерян в headless-пейне интеграционной сессии;
  перепроверить в обычном окне браузера.
- [x] Стоп-сигналы и поворотники видны; секции светофора различимы; `pnpm check` зелёный.

Слито в `main` без правок кода — реализация проверена построчно против карточки и `docs/ARCHITECTURE.md`
(«Рендер»: «Машины: InstancedMesh на класс, позиция интерполируется между двумя последними кадрами по id»,
«Светофоры: инстансы ламп с цветом по signalStates»), `packages/contracts` не тронут (`git diff --stat` пуст),
`pnpm check` зелёный (typecheck, lint, determinism, 274 passed / 27 todo на объединённом `main`). Что проверено:
- `interpolation.ts`: слот = `id % capacity`, снап при смене владельца слота (`ownerId`), лерп по времени иначе;
  `lerpAngle` — кратчайшая дуга; `sampleInterpolated` не экстраполирует за `toTimeS` (клампится в `sim/client.ts`
  через `displaySimTimeS = min(latestFrameSimTimeS, ...)`) — прогон юнит-тестов подтверждает каждый из этих кейсов
  (respawn без лерпа, клампинг альфы, угол через ±π).
- `vehicles.ts`: ёмкость каждого меша = `capacity` (столбы/поворотники — `capacity·2`), индекс = слот, а не плотный
  счётчик — `mesh.count` не меняется, скрытие только через `ZERO_SCALE_MATRIX`; при смене класса в одном слоте без
  кадра простоя старые «личные» детали (штанги троллейбуса) явно обнуляются в `clearIdentityParts` до записи новых —
  проверено юнит-тестом `"clears the previous occupant's parts when a slot is immediately reused..."`.
- `signals.ts`: индекс группы в `signalStates` — по всем группам всех контроллеров, включая пешеходные (не
  рисуются, но считаются) — тест `buildSignalHeadLayouts` фиксирует именно этот сдвиг индекса. Цвета секций
  различимы (`RED_LAMP_COLOR`/`YELLOW_LAMP_COLOR`/`GREEN_LAMP_COLOR`/`OFF_LAMP_COLOR` — четыре разных константы),
  `FLASHING_GREEN` мигает через общий `isBlinkOn`.
- `composeBoxMatrix` (util.ts) даёт согласованную с `ribbon.ts`/`toVec3` конвенцию (map (x,y) → three (x, h, -y),
  heading CCW от +x → `Quaternion.setFromAxisAngle(Y, heading)`) — руками проверено дифференцированием обеих формул
  (совпадают с точностью до используемого в ribbon.ts преобразования).
- Ручная проверка в браузере (`pnpm --filter @atl/web dev`, `/?stress=1` и обычный запуск): сцена монтируется,
  прогрев проходит без ошибок в консоли, `?stress=1` рендерит 20 000 инстансов без воркера. Точный fps на «этой

  это ограничение самого инструмента предпросмотра, а не приложения) — при следующей интеграции стоит перепроверить
