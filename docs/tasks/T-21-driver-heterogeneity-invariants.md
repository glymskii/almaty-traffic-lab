# T-21. Разнородность водителей, финализация gridlock и нарушителей, инварианты

**Пакет:** `packages/sim-core` · **Волна:** 4 · **Уровень:** M · **Размер:** ~500 строк · **Зависит от:** T-11, T-14 · **Разблокирует:** T-22, T-28

## Цель
Убедиться, что каждое распределение из `DriverParams` реально сэмплируется и влияет, довести gridlock и нарушителей
до параметров сценария, реализовать проверку инвариантов в debug-режиме. Закрывает N19 полностью и N26.

## Что сделать
1. Аудит использования `config.driver.*` и `vehicleClasses.*`: таблица «параметр → где используется» в README;
   недостающие подключить (например, `criticalGapPedestrianS`, `politeness`).
2. Gridlock: флаг дисциплины пересэмплировать при `setParams("behavior.gridlockDiscipline")` для новых машин; текущие не трогать.
   Нарушители аналогично для `busLaneViolatorShare`.
3. `runtime/invariants.ts` (`debugInvariants`): после каждого шага — нет NaN/Infinity в массивах, зазор между соседями
   в списке полосы ≥ 0 (наложение = ошибка с описанием: полоса, id, s), скорости в `[0, 1.5·v0]`, `s` в пределах полосы,
   каждая живая машина ровно в одном списке. Ошибка бросает исключение с контекстом.
4. Тесты: N19 вторая часть (дисциплина 1 — поперечный поток не меняется относительно свободного выезда, ±10%);
   N26 (10 минут `crossroads` при насыщении, `debugInvariants: true`, без исключений); для каждого распределения тест
   «sd = 0 vs sd > 0 меняет поведение» (хотя бы через `trajectoryHash`).

## Заметки от T-04 (учесть)
- `sortTrack` сейчас молча чинит порядок машин; в debug-режиме там должна бросаться ошибка о наложении.

- Инвариант зазора: «зазор ≥ 0 и нет наложений», а не «≥ s0»: дискретный IDM с dt 0,1 с может остановить машину в стоячей очереди на дециметры ближе s0 (см. README sim-core, известное свойство модели).
