# T-21. Разнородность водителей, финализация gridlock и нарушителей, инварианты

**Пакет:** `packages/sim-core` · **Волна:** 4 · **Уровень:** M · **Размер:** ~500 строк · **Зависит от:** T-11, T-14 · **Разблокирует:** T-22, T-28

## Цель
Убедиться, что каждое распределение из `DriverParams` реально сэмплируется и влияет, довести gridlock и нарушителей
до параметров сценария, реализовать проверку инвариантов в debug-режиме. Закрывает N19 полностью и N26.

## Что сделать
1. Аудит использования `config.driver.*` и `vehicleClasses.*`: таблица «параметр → где используется» в README;
   недостающие подключить (например, `criticalGapPedestrianS`, `politeness`).
2. Gridlock: флаг дисциплины пересэмплировать при `setParams("behavior.gridlockDiscipline")` для новых машин; текущие не трогать.
   Нарушители аналогично для `busLaneViolatorShare`.
3. `runtime/invariants.ts` (`debugInvariants`): после каждого шага — нет NaN/Infinity в массивах, зазор между соседями
   в списке полосы ≥ 0 (наложение = ошибка с описанием: полоса, id, s), скорости в `[0, 1.5·v0]`, `s` в пределах полосы,
   каждая живая машина ровно в одном списке. Ошибка бросает исключение с контекстом.
4. Тесты: N19 вторая часть (дисциплина 1 — поперечный поток не меняется относительно свободного выезда, ±10%);
   N26 (10 минут `crossroads` при насыщении, `debugInvariants: true`, без исключений); для каждого распределения тест
   «sd = 0 vs sd > 0 меняет поведение» (хотя бы через `trajectoryHash`).

## Заметки от T-11 (учесть)
- **Константы под калибровку.** `CONFLICT_STOP_MARGIN_M = 2,5`, `CONFLICT_ZONE_M = 2`,
  `CONFLICT_CROSSING_MPS = 5` (в `simulation.ts`); `MIN_APPROACH_SPEED_MPS = 3`, `APPROACH_SCAN_M = 40`,
  `APPROACH_SCAN_DEPTH = 4` (в `runtime/intersections.ts`).
- **Критерий «две машины никогда не в одной точке конфликта» держится не при любом спросе.** На
  `crossroads({leftPocketM: 0, leftTurnMode: "permissive"})` при 2400 поездок/ч — 0 событий, при 5000 — 34
  за 540 с. Все они одного вида: машина, уже прошедшая последнее безопасное место ожидания, доезжает точку
  на 4,5–5 м/с, пока приоритетный поток подходит на 12 м/с. Принятый зазор учитывает время освобождения
  точки только через `CONFLICT_CROSSING_MPS`, но не скорость приоритетной машины в момент прибытия;
  `APPROACH_SCAN_M = 40` короче пути приоритетной машины за критический зазор (14 м/с × 6 с ≈ 84 м).
  Эксперимент: `APPROACH_SCAN_M = 100`, `APPROACH_SCAN_DEPTH = 8` убирает нарушения на нерегулируемом
  T-образном узле (2 → 0), но на перекрёстке даёт лишь 34 → 29 — одной константой не обойтись.
- **Разрешённый левый кладёт перекрёсток раньше, чем ожидалось.** При доле левых 0,4 и спросе 1,2×
  насыщения (а также при 0,6× насыщения с долей 0,15) `crossroads` встаёт целиком — из-за этого N09
  пришлось перевести на `leftTurnMode: "protected"`. Реалистичность этого порога — часть вашей калибровки;
  вторая часть N19 (реалистичность доли `gridlockDiscipline`) тоже за вами, сейчас разведено только
  поведение при 0 и 1.
