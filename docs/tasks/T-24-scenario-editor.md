# T-24. Редактор сценариев и применение overrides

**Пакет:** `packages/map-data` + `apps/web` · **Волна:** 5 · **Уровень:** M · **Размер:** ~1100 строк · **Зависит от:** T-08, T-23 · **Разблокирует:** T-26

## Цель
`applyOverrides(network, overrides, config)` в `map-data` и UI-формы редактирования перекрёстка, участка и
глобальных параметров; сценарии хранятся в localStorage, экспортируются/импортируются JSON; применение =
перекомпиляция + перезапуск с тем же сидом.

## Контекст
`docs/CONTRACTS.md` («Scenario и overrides»); `packages/contracts/src/overrides.ts`; T-07 (функции перестроения
коннекторов узла), T-08 (`regenerateController`); `docs/DECISIONS.md` D12.

## Что сделать
1. `map-data/src/compiler/overrides.ts`: применение по видам:
   - `link`: пересобрать полосы линка (`generalLanes`, карманы с длинами, `busLane` добавить/убрать/изменить, `speedLimitKph`),
     затем пересобрать коннекторы и конфликты на обоих узлах линка (T-07) и контроллеры этих узлов (T-08), сохранив ручные
     параметры контроллеров, если для них есть `signal`-overrides; provenance `manual`;
   - `signal`: `regenerateController`; `bus_stop`, `bus_route` (`enabled: false` удаляет маршрут);
   - результат: новая `Network` (исходная не мутируется), `meta.networkId = <base>+<scenarioId>`, integrity обязателен.
   Экспорт `applyOverrides` из `@atl/map-data` (браузерная сборка: без node-модулей в этом пути).
2. UI: клик по узлу `signalized` → форма: по подходам тип левого поворота, зелёные секунды групп, цикл, смещение, пешеходная
   фаза; клик по линку → форма: сквозные полосы, скорость, левый/правый карман, выделенка (вкл, часы, окно правого поворота),
   остановки на линке (в полосе/карман). Кнопка «Применить» создаёт/обновляет override в текущем сценарии.
3. Вкладка «Сценарии»: список, создать/копировать/удалить/переименовать, активный сценарий, кнопка «Запустить» (перекомпиляция
   в главном потоке с индикатором, затем новый воркер с тем же сидом), экспорт JSON, импорт с валидацией `ScenarioSchema`
   и проверкой `networkId`.
4. Подсветка изменённых объектов на карте (контур).
5. Тесты (`map-data`): каждый вид override на `crossroads`/`straightRoad`: integrity пустой, детерминизм, идемпотентность
   (повторное применение того же override не меняет результат), `busLane: null` убирает полосу и коннекторы; UI: редьюсеры
   сценариев и сериализация localStorage.

## Файлы
`packages/map-data/src/compiler/overrides.ts` (+ тесты), `apps/web/src/ui/{ScenariosTab,IntersectionForm,LinkForm}.tsx`,
`src/state/scenarios.ts`.

## Заметки из ревью T-08 (учесть)
- Готова `regenerateController(net, nodeId, set, cfg)` в `packages/map-data/src/signals/regenerate.ts`:
  принимает ровно `SignalOverride["set"]` и мутирует сеть так, что она снова проходит `checkNetworkIntegrity`.
  Порядок применения: `leftTurnModes` и `pedestrianPhase` пересобирают план с нуля, затем `cycleS` масштабирует
  зелёные, затем `greenS` по группам переопределяет фазы (фаза берёт максимум из запрошенных её группами),
  затем `offsetS`. Id групп выведены из линка и зебры (`sg.<linkId>.main`, `sg.<linkId>.arrow_left`,
  `sg.<crosswalkId>.ped`), а не из порядкового номера, поэтому ссылки в `greenS` переживают пересборку.
- `applyOverrides` в `packages/map-data/src/compiler/index.ts` по-прежнему заглушка — это твоя задача.
- Осторожно с `leftTurnModes: "prohibited"` на подходе, у которого есть реальные левые коннекторы: они
  останутся в сети без `signalGroupId` и с `protection: "yield"`. Это допустимо по контракту, но рантайм
  (T-11) обязан считать их непроезжими — проверь на своих тестах.
- `cycleS` масштабирует все зелёные пропорционально, включая фазу стрелки и отдельную пешеходную фазу,
  поэтому сильное укорочение цикла может увести стрелку из диапазона 10–15 с, а пешеходную фазу — ниже
  времени перехода. Если это важно для сценариев, ограничивай значение в UI.

## Заметки из ревью T-23 (учесть)
- Стор `apps/web/src/state/store.ts` уже задаёт паттерн «runtime-safe применяется мгновенно через `sim.setParams`,
  остальное — черновик (`draft...`) до кнопки перезапуска (`applied...` + `restartToken++`)» — переиспользуй его
  для сценарных полей вместо нового механизма. Обрати внимание: у T-23 все три места, где бампается `restartToken`
  (пресеты времени, кнопка «Перезапуск», смена сети), обязаны одинаково переносить `draft*` в `applied*` — если
  в T-24 появится свой черновик поверх сценария, держи это в одном месте (например, общая функция вместо копипасты
  в каждый экшен), иначе легко воспроизвести баг, который был исправлен в этой задаче (один из путей перезапуска
  не переносил черновик и откатывал несохранённое изменение молча).
- Интервалы автобусов (`BusRoute.headwayPeakS/headwayOffpeakS` в `network.ts`/`overrides.ts`) — per-route
  параметры, которые T-23 сознательно не стала пихать в глобальную панель параметров (это не скаляр `SimConfig`).
  Решение владельца: класть их в форму «маршрут» этого редактора, а не заводить `demand.busHeadwayMultiplier`
  в контракте ради глобального множителя — если понадобится глобальный рычаг поверх per-route значений, обсуждать
  отдельно как расширение `packages/contracts`.

## Заметки после ревью T-24 (интеграция в main, учесть в следующих задачах)
- Принято в main как есть после проверки диффа по факту кода (не по отчёту исполнителя): `applyOverrides`
  корректно пересобирает полосы/коннекторы/конфликты/зебры/базовый план строго для узлов затронутых линков
  (T-07 scope), детерминизм/идемпотентность подтверждены тестами и вручную прослежены по коду
  (`packages/map-data/src/compiler/overrides.ts`); `packages/contracts` не тронут.
- Исправлен на main (после мержа) реальный дефект UI, не пойманный тестами исполнителя: `IntersectionForm`/
  `LinkForm` брали начальные значения формы только из `viewport.network` (текущей отрендеренной сети), а не из
  уже сохранённого override активного сценария. Конкретный сценарий отказа: создать сценарий A, задать override
  для линка/узла, НЕ нажимать «Запустить» (сеть на экране остаётся baseline), затем снова кликнуть по тому же
  объекту — форма показывала значения из baseline, а не из сохранённого override; повторное «Применить» без
  единого изменения поля молча затирало override дефолтными значениями. Правка — `initialState()` в обоих
  файлах теперь накладывает `findOverride(scenario, kind, id)?.set` поверх сетевых дефолтов, поле за полем;
  добавлены регрессионные тесты в `apps/web/test/ScenariosTab.test.tsx` («re-opens ... with the scenario's
  already-saved override»). Тот же паттерн стоит проверить в любой будущей форме редактора (T-26 и далее),
  которая читает `viewport.network` для инициализации, а не только `scenario.overrides`.
- Не реализовано (при этом не блокирует критерий приёмки): пункт «остановки на линке (в полосе/карман)» из
  §2 карточки и рекомендация ревью T-23 «форма маршрута» для `headwayPeakS/headwayOffpeakS` — обе фичи имеют
  полную поддержку на уровне контрактов/`applyOverrides` (`BusStopOverrideSchema`, `BusRouteOverrideSchema`,
  `applyBusStopOverride`/`applyBusRouteOverride` в `overrides.ts`), но в `apps/web` нет ни одной формы, которая
  бы их создавала — `bus_stop`/`bus_route` overrides сейчас достижимы только через ручной JSON-импорт сценария.
  Если это нужно продукту, заводить отдельной небольшой задачей (форма остановки в `LinkForm` + форма маршрута)
  до/вместе с T-26, а не считать T-24 закрывающей эту часть цели карточки.
- `Scenario.params` (deep-partial `SimConfigPatch`, для «глобальных параметров» из раздела «Цель» карточки)
  остаётся в контракте, но нигде не используется: в `apps/web` нет формы, которая его заполняет, и
  `ui/App.tsx`'s `configPatch` для Viewport строится только из `startTimeMin`/`runtimeParams`/`appliedRestartParams`
  — `appliedScenario.params` в него не подмешивается. Пока это не проблема (поле всегда `{}`), но если T-26 или
  другая задача добавит форму глобальных параметров сценария, не забыть смёрджить `appliedScenario.params` в
  `configPatch` в `App.tsx`, иначе сохранённые значения молча не будут применяться при «Запустить».

## Заметки от T-12 (учесть)
- **Аттрактор на узле-воротах теряет `weightIn`.** В `demand/od.ts` назначения собираются сначала по
  воротам (`weightOut > 0`), затем по аттракторам с `if (seen.has(node)) continue` — вес аттрактора,
  стоящего на том же узле, отбрасывается молча, а не складывается с воротным. На скомпилированных сетях
  ворота лежат на границе bbox, поэтому сейчас это не стреляет; если редактор позволит поставить
  аттрактор на узел-ворота, надо либо складывать веса в `OdModel`, либо запрещать это в валидации.
