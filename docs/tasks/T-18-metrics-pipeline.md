# T-18. Метрики: сегменты, окна, задержки, корневые причины

**Пакет:** `packages/sim-core` · **Волна:** 3 · **Уровень:** S · **Размер:** ~900 строк · **Зависит от:** T-11 (T-12 для реальных поездок) · **Разблокирует:** T-19, T-20, T-25

## Цель
Реализовать `writeMetrics()` и `totals`: агрегаты по сегментам за скользящее окно, задержки в машинах и людях,
V/C, распространение корневой причины по очередям. Закрывает N07 и вторую проверку N24 (наследование причины).

## Контекст
`docs/ARCHITECTURE.md` («Причины и распространение корневой причины», «Метрики и детектор»); `packages/contracts/src/{metrics,causes,sim-config}.ts`;
`docs/NUANCES.md` («Как считать поток, задержку, остановку», N07, N23, N24).

## Что сделать
1. `metrics/segments.ts`: индекс `laneIdx, s → segmentIdx` (по кумулятивным границам), `approachNodeId` для последнего сегмента
   перед узлом. Коннекторы относятся к последнему сегменту своей входящей полосы.
2. `metrics/rootCause.ts`: за один проход по каждому списку полосы от головы к хвосту: `root[i] = cause[i] === leader && (v[lead] < 0.5·v0 ∨ stopped(lead)) ? root[lead] : cause[i]`; через границу коннектор → полоса учитывать лидера на следующей
   полосе; глубина ≤ 200. Машина, ждущая на стоп-линии из-за `downstream_spillback`, передаёт эту причину очереди.
3. `metrics/accumulators.ts`: раз в `sampleIntervalS` для каждого сегмента: Σv и n (скорость), n/длина (плотность),
   счётчик пересечений конца (поток), длина стоящей части (от последней стоящей до головы), Σ задержки
   `dt·max(0, 1 − v/v_free)` по машинам и ×наполненность, Σ задержки по корневой причине (матрица), остановки.
   Кольцевой буфер по `windowS / sampleIntervalS` семплов; `writeMetrics` сворачивает окно в `MetricsFrame`.
4. V/C: поток через конец сегмента / (1800 × доля зелёного для сегментов-подходов, иначе 1800).
5. `totals`: активные/завершённые, суммарные задержки после прогрева, средние скорости по классам (по поездкам за окно),
   доля стоящих, доля сегментов E/F.
6. Тесты: N07 (`greenSplitNS` 0.4 vs 0.6 → задержки NS/EW монотонны); N24 вторая проверка (очередь за `pocket_spillback`
   наследует причину: доля ≥ 0.8 на сегменте); окно даёт средние по времени (синтетический прогон с известной скоростью);
   `causeShare` строки суммируются в 1 или 0; производительность: метрики на 20 000 машин < 2 мс/семпл.
