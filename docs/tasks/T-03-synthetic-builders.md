# T-03. Синтетические мини-сети для тестов

**Пакет:** `packages/sim-core` (test/fixtures) · **Волна:** 1 · **Уровень:** M · **Размер:** ~900 строк · **Зависит от:** — · **Разблокирует:** T-08, T-09, T-10, T-11, T-12, T-14…T-22

## Цель
Реализовать билдеры `crossroads`, `tJunction`, `mergeRamp`, `corridor` из `packages/sim-core/test/fixtures/builders.ts`
так, чтобы каждый возвращал полную консистентную `Network` (полосы, коннекторы с точками конфликта, зебры,
контроллер светофора, ворота). На этих сетях доказываются все нюансы из `docs/NUANCES.md`.

## Контекст
`CLAUDE.md`; `docs/CONTRACTS.md`; `docs/NUANCES.md` (какие опции нужны тестам); `packages/contracts/src/network.ts`,
`integrity.ts`; реализованный `straightRoad` как образец стиля; `docs/ARCHITECTURE.md` разделы «Светофоры»,
«Перекрёстки и конфликты», «Карманы и выделенки».

## Контракты
Только потребляет. Сигнатуры опций билдеров уже объявлены; можно добавлять **опциональные** поля в опции билдеров
(это тестовый код, не контракты).

## Что сделать
1. **Геометрия.** Общий хелпер: перекрёсток в (0,0), плечи по сторонам света длиной `armLengthM` (по умолчанию 300 м),
   ворота на концах. Линки в обе стороны на каждом плече со смещением осевой на половину ширины проезжей части.
   Полосы: `lanes` сквозных (по умолчанию 2) + левый карман `leftPocketM` (по умолчанию 60; 0 = нет кармана, тогда
   крайняя левая сквозная получает `turns: [left, through]`) + опционально выделенка на EW (`busLaneEW`).
2. **Коннекторы.** Для каждого подхода: left из кармана (или из левой сквозной), through из сквозных в соответствующие
   полосы выхода, right из крайней правой. Геометрия: кубическая Безье между концами полос, длина по полилинии из 8 точек.
   Точки конфликта: пересечения полилиний между движениями разных подходов + левый против встречного прямого; записи
   симметричные, `priority: "signal"` при светофоре.
3. **Зебры** (`crosswalks: true`): на каждом плече поперёк выхода, `connectorIds` = все движения, выезжающие на это плечо,
   двусторонние ссылки. Пешеходная группа зелёная вместе с параллельным сквозным движением.
4. **Контроллер.** Группы по подходам: основная (through + right + permissive left), `arrow_left` при
   `leftTurnMode: protected|protected_permissive`; фазы: 2-фазный план NS/EW с `greenSplitNS` (по умолчанию 0.5)
   и `cycleS` (по умолчанию 90), защищённые левые как отдельные ведущие фазы по 12 с. `leftTurnModes` заполнить
   для всех четырёх подходов; `prohibited` ⇒ левые коннекторы не создаются.
5. **tJunction:** главная EW, второстепенная с юга; `signalized: false` ⇒ коннекторы второстепенной `yield`, главной `priority`,
   конфликты с `priority: this/other`; `signalized: true` ⇒ 2 фазы.
6. **mergeRamp:** главная EW `mainLanes` (2) и длиной `mainLengthM` (1500), узел `merge` на 500 м, съезд с юго-запада
   под углом 20°, коннектор `merge` с `protection: yield`, конфликт с крайней правой главной; `accelLaneM > 0` ⇒
   дополнительная правая полоса главной после узла длиной `accelLaneM` с `endS < lengthM` и `turns: [merge]`.
7. **corridor:** `intersections` (4) крестовых перекрёстков через `spacingM` (400) на общей магистрали EW, поперечные
   улицы короткие с воротами; `offsetsS` в контроллеры; `parallelStreet: true` добавляет параллельную residential-улицу
   в 200 м севернее, соединённую с поперечными (для N21).
8. Хелперы для тестов: `saturationMultiplier(net)` (оценка множителя спроса, при котором главный подход перегружен на 20%,
   по ёмкости 1800 веh/ч/полосу × доля зелёного) и `approachSegments(net, linkId)` для выборки сегментов.
9. Тесты на каждый билдер: `parseNetwork` + `checkNetworkIntegrity` пустой; ожидаемое число коннекторов; симметрия конфликтов;
   `prohibited` без левых; `busLaneEW` с `kind: bus`.
