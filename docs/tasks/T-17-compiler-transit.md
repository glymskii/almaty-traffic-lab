# T-17. Компилятор, часть 3: маршруты и остановки ОТ из OSM

**Пакет:** `packages/map-data` · **Волна:** 3 · **Уровень:** M · **Размер:** ~700 строк · **Зависит от:** T-07 · **Разблокирует:** T-29

## Цель
Из отношений `route=bus|trolleybus` и узлов остановок построить `BusRoute` и `BusStop`, обрезанные по bbox,
с интервалами по умолчанию и происхождением. В тестовом квадрате ожидается ~39 отношений и 93 остановки.

## Контекст
`packages/contracts/src/network.ts` (`BusRoute`, `BusStop`); `docs/DECISIONS.md` D10; снимок T-01 (слой `transit`);
T-02 (маппинг OSM way → линки; нужна таблица `wayId → linkIds по направлениям`, экспортировать из T-02, если её нет).

## Что сделать
1. Для каждого отношения: упорядоченные way-члены (роль пустая/`forward`/`backward`), выкинуть `platform`/`stop` роли;
   восстановить направление обхода по общим узлам соседних way; отобразить в цепочку линков нужного направления;
   разрывы (way вне bbox или не дорога) режут маршрут на куски — оставить самый длинный кусок внутри bbox, если ≥ 2 линков.
2. `entryNodeId`/`exitNodeId` = начало первого/конец последнего линка куска (обычно ворота или узел внутри).
3. Остановки: узлы `highway=bus_stop`/`platform` привязать к ближайшему линку маршрута в 30 м (по стороне дороги:
   остановка справа по ходу), `laneId` = крайняя правая, `s` = проекция; `kind: in_lane` (`default`), `bay` при теге
   `bus_bay=*`/`highway=bus_stop`+`bus_bay`. Остановки без маршрутов — не создавать.
4. Интервалы: тег `interval`/`interval:peak` (минуты) если есть (`osm`), иначе 480/900 с (`default`). `ref` из тега,
   `kind` по `route`.
5. Отчёт допущений: маршрутов всего/обрезано/выброшено, остановок привязано/не привязано.
6. Тесты: синтетическая фикстура отношения из трёх way с одним `backward`; на маленьком квадрате ≥ 25 маршрутов проходят integrity,
   ≥ 60 остановок привязаны.

## Заметки после ревью интегратора (слияние в main)
- `packages/contracts` не тронут (diff --stat пуст) — подтверждено перед слиянием. Слияние `--no-ff` прошло без конфликтов, `pnpm check` зелёный без единой правки: typecheck/lint/determinism/тесты (343 passed, 25 todo, 4 skip) все прошли как есть.
- Реальный снимок маленького квадрата: 34 отношения bus/trolleybus в снимке, 25 скомпилировано (все 25 — с обрезкой до самого длинного куска), 9 выброшено (<2 линков внутри bbox); 99 кандидатов-остановок, 69 привязано, 30 не привязано (>30 м от любого линка маршрута). Совпадает с числами из отчёта исполнителя. Число ~39/93 в контексте карточки — грубая оценка на момент постановки задачи, не жёсткий таргет; фактический снимок даёт другие цифры, но критерий приёмки (≥25 маршрутов, ≥60 остановок, integrity пустой) выполнен с запасом.
- Осознанное отступление от буквального текста п.3 «Остановки без маршрутов — не создавать»: реализация привязывает остановку к ближайшему линку **любого** way, встречающегося хоть в одном отношении bus/trolleybus внутри bbox, а не только к линкам итогового (обрезанного) `BusRoute.linkIds`. Из-за этого возможна «осиротевшая» `BusStop`, которая существует в `network.busStops`, но не входит ни в один `BusRoute.stopIds` (тест `transit.test.ts` — «a gap keeps only the longest piece» — специально это проверяет). `checkNetworkIntegrity` такого не запрещает, поведение задокументировано в README и осознанно — иначе терялись бы реальные остановки на кусках улицы, отрезанных при обрезке маршрута до самого длинного куска. Решение принято интегратором как приемлемое (не блокирует слияние), но **T-27 (городские слои)** и **T-14 (sim-core, выделенки/остановки)** должны это учесть: `net.busStops` не является подмножеством `⋃ route.stopIds`, и рендер/симуляция не должны падать или вести себя странно на остановке без маршрута.
