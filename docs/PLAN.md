# План разработки Almaty Traffic Lab

Дата: 7 сентября 2026. Владелец плана: сильная модель (Claude Fable 5.1) в этом окне. Исполнители задач:
агенты в отдельных окнах по карточкам `docs/tasks/T-NN-*.md`. Решения, на которых план стоит: `DECISIONS.md`.

## Цель и критерий успеха
Показать, что с помощью ИИ можно собрать полноценную 3D-симуляцию движения города с учётом нюансов,
на условных данных, с заменяемым источником. Критерий успеха исполняемый: все тесты нюансов N01–N26
зелёные (`NUANCES.md`), N27 проходит бенчмарк, и демо на большом полигоне центра Алматы показывает
Топ-10 узких мест с объяснением причин и сравнением A/B.

## Объём (что входит)
1. Импорт OSM плитками и компилятор в `network.json` с генератором допущений и происхождением атрибутов.
2. Микросимуляция IDM + MOBIL: полосы, карманы, четыре типа левого поворота, доп. секции, выделенки,
   остановки, пешеходы, gridlock, слияния, навигаторные перестроения, разнородные водители.
3. Метрики по сегментам, детектор узких мест, объяснение через связывающие ограничения, рекомендации.
4. 3D-рендер: процедурное полотно с разметкой, светофоры с секциями, инстансы машин, здания и парки из OSM.
5. UI: панели, тепловая карта, Топ-N, подлёт камеры, редактор сценариев формами, A/B на двух воркерах.
6. Headless CLI, регрессия, бенчмарк, smoke-тест, деплой.

Вне объёма: рисование новой геометрии, адаптивные светофоры, BRT по центру, приоритет ОТ, рельеф, тени,
LLM-объяснения, бэкенд.

## Фаза 0 (сделано в этой сессии)
Скелет монорепо; `packages/contracts` со схемами сети, конфига, сценариев, причин, метрик, буферов и протокола;
`checkNetworkIntegrity`; `Rng`; интерфейс `Simulation`; билдер `straightRoad`; 35 заготовок тестов нюансов;
CLI-заглушки; `CLAUDE.md`; документация; 31 карточка задач. `pnpm check` зелёный.

## Вехи (что можно показать)
- **M1, после волны 1:** сеть маленького квадрата отрисована в 3D, по прямой дороге едут машины из воркера.
- **M2, после волны 2:** машины ездят по центру Алматы через светофоры, поворачивают, перестраиваются, стоят в очередях.
- **M3, после волны 4:** CLI печатает Топ-10 узких мест с причинами; все нюансы доказаны тестами.
- **M4, после волны 5:** демо для урбаниста: тепловая карта, объяснения, сценарии, A/B.
- **M5, после волны 6:** большой полигон, 20 тысяч машин, ссылка на Vercel.

## Процесс передачи задач
1. Владелец открывает волну: проверяет, что зависимости в `main`, при необходимости обновляет карточки.
2. Для каждой задачи открывается новое окно агента с промптом: «Прочитай CLAUDE.md и docs/tasks/T-NN-….md,
   выполни задачу, заверши отчётом по шаблону». Уровень модели по колонке «Уровень».
3. Агент работает в своём worktree (`../atl-T-NN`, ветка `task/T-NN`), заканчивает `pnpm check` и отчётом.
4. Владелец делает ревью диффа против контрактов и критериев карточки, сливает в `main`, обновляет `PLAN.md`
   (статус) и, если в отчёте есть «Требуется решение», принимает решение и фиксирует его в `DECISIONS.md`.
5. После слияния всей волны: интеграционный прогон (CLI на маленьком квадрате, `pnpm dev`), затем следующая волна.

## Риски и меры
| Риск | Мера |
|---|---|
| Расползание контрактов агентами | Заморозка `packages/contracts`, правило «Требуется решение», ревью между волнами |
| Симуляция «взрывается» (наложения, NaN) | Инварианты в debug (T-21), тесты N26, полунеявная интеграция, ограничения ускорений |
| Генератор планов даёт абсурд на 407 перекрёстках | Отчёт допущений компилятора, QA-задача T-29 с выборочной проверкой и правилами-предохранителями |
| Производительность ниже цели | Бюджет машин, `rtFactor` в UI, T-28 до масштабирования; SoA с первого дня |
| Overpass нестабилен | Плитки, повторы, зеркала, снимок в репо; сеть не нужна для разработки |
| Агенты низкого уровня застревают на тонкой логике | Уровни в карточках: конфликты, MOBIL, детектор только сильной модели |
| Дрейф между синтетическими фикстурами и реальной сетью | Одни и те же контракты и `checkNetworkIntegrity`; T-29 гоняет реальную сеть через CLI |
