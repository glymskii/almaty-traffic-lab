# Журнал решений

Формат: контекст → решение → последствия. Решения приняты владельцем проекта 7 сентября 2026 в ходе
структурированного интервью. Изменение любого решения фиксируется здесь новой записью, а не правкой старой.

## D1. Цель проекта
**Контекст.** Исходная формулировка: показать узкие места трафика Алматы. В ходе обсуждения цель уточнена.
**Решение.** Цель: продемонстрировать, что с помощью ИИ можно за короткий срок собрать полноценную симуляцию
городского движения с учётом нюансов, на условных данных и с заменяемым источником. Алматы служит
демонстрацией конвейера, не картой для принятия решений. Если акимат или жители заинтересуются, проект
переделывается с точными данными.
**Последствия.** Ценность в конвейере «bbox → сеть с допущениями → симуляция → объяснение», а не в выверенности
конкретных перекрёстков. Ручных данных нет (см. D5).

## D2. Форма результата и аудитория
**Решение.** Интерактивное статическое веб-приложение. Аудитория: урбанисты и акимат.
**Последствия.** Панель объяснений «почему здесь пробка» и сравнение «до/после» входят в ядро продукта.
Метрики в терминах, понятных урбанисту: задержка, V/C, уровень обслуживания A–F, человеко-часы.

## D3. Стек
**Решение.** Three.js (vanilla) + TypeScript + Vite, React только для UI, pnpm workspaces, Vitest, Biome.
Отвергнуты: React Three Fiber (лишний слой над горячим рендер-циклом), Babylon, Unity/Unreal (нет headless-тестов,
тяжёлый веб-экспорт).
**Последствия.** Рендер на `InstancedMesh`, UI на React, ядро на чистом TS.

## D4. Охват
**Решение.** Большой полигон «весь центр Алматы»: Райымбека (север), Аль-Фараби (юг), Гагарина (запад), Достык
(восток); ~49 км², 407 регулируемых перекрёстков, 553 км дорог по OSM. Bbox — параметр; маленький квадрат
Абая–Тимирязева × Ауэзова–Сейфуллина используется для тестов и разработки.
**Последствия.** Бюджет машин (по умолчанию 20 000) как параметр: спрос масштабируется под бюджет, UI показывает
коэффициент реального времени. Импорт плитками с повторами и зеркалами Overpass. Узлы слияния (развязки
Аль-Фараби и Райымбека) как отдельный тип узла.

## D5. Данные
**Решение.** Гибрид: одноразовый снимок OSM в репозитории (сжатый), компилятор с генератором допущений, слой
`overrides` как механизм. **Ноль ручных данных**: генератор заполняет всё. У каждого атрибута происхождение
`osm` / `default` / `manual`, показывается в UI.
**Последствия.** Демо честно помечает допущения. Масштаб помогает: среди 407 перекрёстков каждый эффект где-то
проявится, детектор его найдёт.

## D6. Модель движения
**Решение.** Микроскопическая: IDM (продольное) + MOBIL (перестроения), шаг 0,1 с, полосы как сущности,
карманы со spillback, четыре типа левого поворота, разнородные водители. Параметры «дисциплина на перекрёстке»
(gridlock) и «доля нарушителей выделенки» включены и настраиваемы.
**Последствия.** Явления, которые движок обязан показывать, перечислены в `docs/NUANCES.md` как исполняемые тесты.

## D7. Архитектура
**Решение.** Пакеты `contracts`, `map-data`, `sim-core`, `sim-worker`, `apps/web`. Контракт `network.json`
как единственный вход симуляции. Состояние наружу через типизированные массивы и transferable-буферы
(пинг-понг), без `SharedArrayBuffer` (не хотим COOP/COEP). Метрики отдельно от кадров, раз в секунду.
**Сценарий = перекомпиляция сети + перезапуск с тем же сидом.** На лету только безопасные параметры.
**Последствия.** Границы пакетов = границы задач для агентов. Уточнение при реализации: схемы вынесены
в отдельный пакет `contracts`, чтобы правило «не менять контракты» было привязано к одному пути.

## D8. Светофоры
**Решение.** Фиксированные планы по сигнальным группам (по манёврам), доп. секции как группы `arrow_*`,
четыре типа левого поворота на подход, пешеходы как абстрактный поток с уступанием (без 3D-людей, точки на зебре),
генератор планов по Веберу для всех перекрёстков, местная последовательность сигналов (мигающий зелёный,
красный+жёлтый). Адаптивное управление вне объёма.

## D9. Спрос и маршруты
**Решение.** Ворота на границе + точки притяжения из OSM POI, профиль по часам, кратчайшие пути с шумом,
доля «навигаторных» водителей (перестраивают маршрут по текущим временам проезда), автобусы по расписанию,
прогрев 5–10 минут ускоренно, пресеты времени суток.

## D10. Автобусы
**Решение.** Маршруты и остановки из OSM (39 отношений, 93 остановки в тестовом квадрате), интервалы по умолчанию
8/15 минут, остановка «в полосе» по умолчанию, выделенка для автобусов и троллейбусов, въезд легковых за 50 м
до правого поворота, доля нарушителей, такси как переключатель. Метрики в людях через коэффициенты
наполненности (1,5 / 40 / 20). BRT по центру и приоритет на светофорах вне объёма.

## D11. Узкие места
**Решение.** Три условия: скорость ниже 30% свободной, очередь держится (персистентность), ниже по потоку
свободнее. Ранжирование по накопленной задержке (машино- и человеко-часы), Топ-N, V/C, уровень A–F.
Объяснение через **связывающее ограничение** каждой машины и распространение корневой причины по очереди.
Рекомендации правилами (причина → сценарий). LLM-объяснения позже.

## D12. Сценарии
**Решение.** Редактирование формами (перекрёсток, участок, глобальные параметры), без рисования геометрии.
Два воркера A/B с одним сидом, одно 3D-окно с переключателем, панель дельт и «новые узкие места».
localStorage + экспорт/импорт JSON. Без бэкенда.

## D13. 3D
**Решение.** Процедурный low-poly, разметка из сети, светофоры с видимыми секциями, инстансы машин со
стоп-сигналами, здания и парки из OSM, плоский рельеф, без теней и пост-обработки. Ассеты только процедурные.

## D14. Проверка
**Решение.** Полный детерминизм ядра, headless CLI, тест на каждый нюанс на синтетической мини-сети,
регрессия по агрегатам, бенчмарк, инварианты в debug, `pnpm check` как DoD, один smoke-тест Playwright для UI.

## D15. Делегирование
**Решение.** Контракты, фикстуры и список тестов пишет сильная модель; агенты реализуют по карточкам
`docs/tasks/T-NN` в 6 волнах; worktree на задачу; ревью между волнами; уровни моделей в карточках; карточки
на русском, код на английском. Агент не меняет контракты, а пишет «Требуется решение».

## D16. Репозиторий и деплой
**Решение.** Приватный GitHub-репозиторий `almaty-traffic-lab`, рабочее имя «Almaty Traffic Lab», скоуп пакетов
`@atl/*`. Снимки данных в репо сжатыми. Атрибуция ODbL в UI. Деплой на Vercel в волне 6 по команде владельца.
Лицензия кода отложена.
