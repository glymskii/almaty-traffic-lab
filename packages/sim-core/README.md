# @atl/sim-core

Чистая детерминированная микросимуляция движения: IDM (продольное), позже MOBIL, светофоры, перекрёстки,
маршруты, автобусы, пешеходы, метрики и детектор узких мест. Без DOM, Three, таймеров и `Math.random`.
Единственная точка входа: `createSimulation({ network, config, scenarioId })` → интерфейс `Simulation`
(`src/simulation.ts`, сигнатуры заморожены). Воркер, CLI и тесты используют только его.

Состояние после T-10: движение по полосам и коннекторам с работающими светофорами и перестроениями
MOBIL (карманы, выделенки, конец полосы); конфликты уступания в перекрёстке — T-11, маршруты — T-12.
`writeMetrics` возвращает нули, `report` — только `totals` без `items`.

## Соглашения
- Координаты: `x` восток, `y` север, метры от центра bbox. Скорости м/с, ускорения м/с², время симуляции в секундах,
  время суток в минутах от полуночи. Курс в радианах против часовой стрелки от +x.
- **Трек** (track) — полоса или коннектор в одном индексном пространстве: полосы занимают `[0, laneCount)`,
  коннекторы `[laneCount, trackCount)`. Машина всегда ровно на одном треке.
- **`s` на полосе измеряется вдоль линка** (не вдоль полосы): все полосы одного линка делят шкалу, карман живёт
  в `[startS, endS]`, перестроение (T-10) сохраняет `s`. На коннекторе `s ∈ [0, lengthM]`.
- `s` — положение переднего бампера; машина занимает `[s − length, s]`. Зазор до лидера: `s_л − length_л − s`.

## Структуры данных

### `runtime/network.ts`: `RuntimeNetwork`
Плоское представление `Network` с целочисленными индексами; строится один раз, не меняется.
- Узлы: `nodeKind`, `nodeX/Y`. Линки: `linkFrom/To`, `linkLengthM`, `linkSpeedMps`, CSR-список полос `linkLanes`.
- Треки: `trackStartS/EndS`, `trackSpeedMps` (коннектор: минимум двух линков), `trackPoly` (индекс полилинии),
  `trackOffsetM` (боковое смещение полосы вправо от оси линка), `trackAllowedMask` (биты классов, см. `classBit`),
  `trackLink`, `trackNextByClass[track·4 + cls]` — следующий трек для класса или −1 (продолжения нет),
  `trackIsExit` — полоса доходит до конца линка в узле `gate` или `dead_end` (только там машина покидает сеть).
- Полосы: `lanePos`, соседи `laneLeft/laneRight` (проверка пересечения по `s` — `lanesOverlapAt`),
  `laneReachesLinkEnd`, CSR-список выходных коннекторов `laneConnList`.
- Коннекторы: `connFromLane`, `connToLane`, `connViaNode`, `connTurn` (код манёвра, см. `runtime/turns.ts`).
- Полилинии (линки, затем коннекторы) в одной таблице вершин `px/py/pcum` с направлением сегмента `segUx/segUy/segAngle`;
  `polyScale = длина полилинии / заявленная длина` переводит `s` в расстояние вдоль вершин. `locate(poly, d, hint)` ищет
  сегмент от кэшированного индекса. Положение машины на полосе = точка оси линка + `offset · правая нормаль`.
- Ворота: `gateShare` (доля спроса по `weightIn` среди ворот с входными полосами), CSR входных полос `gateLanes`
  (полосы с `startS = 0` входных линков), `entryLaneCount`.
- Сегменты метрик: полоса режется на `round(len / segmentLengthM)` равных кусков (`laneSegStart/Count/LengthM`);
  последний сегмент полосы, доходящей до конца линка, получает `approachNodeId`. Коннекторы сегментов не имеют.
  Дескрипторы заморожены (`Object.freeze`), `segments()` отдаёт новый массив тех же объектов.
- `signalGroupIds` (контроллеры в порядке сети, группы в порядке контроллера) и `crosswalkIds` — порядок для кадров;
  `signalGroupIndex` — обратная карта id → индекс (тот же порядок, разделяется с `runtime/signals.ts`);
  `groupIsArrow` — 1 для секций `arrow_left/arrow_right`, иначе 0 (main). Для коннекторов (по треку):
  `connSignalGroup` (глобальный индекс группы или −1, если не сигнализирован) и `connProtection`
  (см. `ProtectionCode`) — индексы под T-09/T-11.

### `runtime/lanes.ts`: `LaneRuntime`
Права доступа и «обслуживаемые манёвры» полос (T-10); строится один раз рядом с `RuntimeNetwork`, индексы те же.
- `turnMaskByClass[полоса·4 + класс]` — битовая маска манёвров, которые класс реально может выполнить с полосы
  (по её **коннекторам**, а не по тегу `lane.turns`: компилятор мог убрать движение). `linkTurnMaskByClass` — то же
  объединением по полосам линка, из него берётся случайный манёвр при входе на линк.
- `isBusLane`, `isPocket`, окно действия выделенки `busActiveFromMin/ToMin`, `busRightWindowM`.
- `serves(полоса, класс, манёвр)` — с полосы можно завершить манёвр (или полоса выходит из сети, `trackIsExit`).
- `mayAdmit` / `admitsAt` — доступ без учёта и с учётом положения: базовая маска `lane.allowed`, плюс исключения
  выделенки — вне часов действия полоса общая, `BUS_LANE_VIOLATOR` едет всегда, `taxi` при
  `taxisAllowedInBusLanes`, легковая с манёвром `right` — в последних `carsMayEnterForRightTurnWithinM` метрах.
- `targetLane(...)` — ближайшая по индексу полоса линка, которая обслуживает манёвр и допускает класс
  (при равенстве — левее), или −1, если текущая полоса уже подходит.
- `connectorFor(полоса, класс, манёвр)` — коннектор нужного манёвра, иначе `trackNextByClass` (запасной вариант).

### `runtime/signals.ts`: `SignalRuntime`
Автомат состояний контроллеров (T-09). Для каждого контроллера строится таблица «шаг цикла (шаг `dtS`) →
состояние каждой его группы»: сначала весь цикл заполняется дефолтом (`RED` для `main`, `OFF` для
`arrow_*`), затем для каждой фазы и каждой её `greenGroupIds` — `GREEN`, последние `flashingGreenS` секунд
`FLASHING_GREEN`, а для `main`-групп ещё `YELLOW` на `phase.yellowS` и (отдельным проходом) `RED_YELLOW`
на последние `redYellowS` секунд перед следующим стартом её же зелёного. У `arrow_*` после `FLASHING_GREEN`
сразу `OFF` — ни `YELLOW`, ни `RED_YELLOW`, ни `RED` доп. секция не показывает. `stateAt(groupIdx, simTimeS)`
учитывает `offsetS` контроллера (сдвиг начала цикла) и ищет ячейку с шагом `dtS` (защита от ошибок
округления — `EPS`); `computeStates(simTimeS)` заполняет `groupState` (глобальный порядок) для всех групп
разом — O(число групп) на шаг, поэтому 400 контроллеров укладываются далеко в бюджет 0,3 мс/шаг. Тип
конструктора (`SignalControllerTiming`) — сознательно урезанный срез `SignalController`: только то, что
нужно автомату (`offsetS`, `groups[].id/section`, `phases[].greenGroupIds/greenS/yellowS/allRedS`), поэтому
тестовые фикстуры не обязаны заполнять остальные обязательные поля схемы (`id`, `nodeId`, `provenance`, …).

### `runtime/vehicles.ts`: `VehiclePool`
Пул ёмкости `demand.vehicleBudget`, все массивы выделены в конструкторе; `step()` не аллоцирует.
- Идентичность и положение: `id` (стабильный, с 1, не переиспользуется), `track` (−1 = свободный слот), `nextTrack`,
  `s`, `v`, `a`, мировые `x/y/heading` (обновляются в конце шага), `geomSeg` (кэш сегмента полилинии).
- Выбор полосы (T-10): `intendedTurn` (манёвр в конце текущего линка), `targetLane` (обязательная целевая полоса
  или −1), `laneChangeEndS` (конец манёвра, он же ограничитель частоты), `laneChangeFromOffsetM`, `laneChangeDir`.
- Машина и водитель: `cls`, `length`, `speedFactor` (желаемая скорость = лимит трека × фактор водителя × фактор класса),
  `timeHeadway`, `minGap`, `maxAccel`, `comfortDecel`, `politeness`, `laneChangeThreshold`, `gapLeftTurn`, `gapMerge`,
  `gapPedestrian`, `occupancy`. Все распределения сэмплируются при появлении в фиксированном порядке (`models/driver.ts`).
- Состояние: `flags` = `persistentFlags | пошаговые` (`BRAKING`, `STOPPED`, `IN_INTERSECTION` пересчитываются каждый
  шаг; `BUS_LANE_VIOLATOR`, `NAVIGATOR`, `DWELLING`, `BLINKER_*` ставят другие подсистемы в `persistentFlags`, ядро их
  не трогает), `cause`, `rootCause`, `spawnTimeS`, `freeFlowTimeS`, `stops`, `countsInStats`.
- Списки по трекам: двусвязный список, упорядоченный по `s`: `trackHead` (самая дальняя машина), `trackTail`
  (ближайшая к началу), `ahead[i]` — лидер, `behind[i]` — последователь. Поиск лидера O(1); вставка от хвоста
  (`insert`), удаление (`remove`), страховочная сортировка вставками (`sortTrack`).
- Свободные слоты: LIFO-стек, `highWater` — верхняя граница занятых слотов, порядок обработки — по индексу слота.

### Прочее
- `runtime/clock.ts`: `simTimeS = stepIndex · dtS` (без дрейфа), `timeOfDayMin = (startTimeMin + simTimeS/60) mod 1440`.
- `runtime/trajectory-hash.ts`: FNV-1a по `(id, round(x·100), round(y·100), round(v·100))` каждой машины, суммы за шаг
  (независимо от порядка) сворачиваются в два 32-битных аккумулятора на каждом шаге → 16 hex-символов.
- `models/mobil.ts`: чистые функции MOBIL. Безопасность `a_нов.последователь ≥ −4 м/с²` (`mobilSafe`); стимул
  `(a_нов − a_стар) + p·(Δa обоих последователей)` (`mobilIncentive`) сравнивается с порогом водителя
  `laneChangeThresholdMps2`. Бонус обязательности `mandatoryBias(d, lookahead)`: 0 при `d ≥ laneSelectionLookaheadM`,
  линейный рост до 4 м/с² и `+∞` (форсирование, остаётся только критерий безопасности) при `d ≤ 30 м`.
- `models/idm.ts`: `a = a_max·[1 − (v/v0)⁴ − (s*/gap)²]`, `s* = s0 + max(0, v·T + v·Δv / (2√(a_max·b)))`,
  результат ограничен снизу `−IDM_MAX_DECEL` (8 м/с²). Известное свойство дискретного IDM (шаг 0,1 с): подъезжая
  к стоящему лидеру, машина может остановиться на несколько дециметров ближе `s0` (равновесие достигается
  асимптотически, а назад машина не едет); наложений при этом нет, зазор остаётся положительным.
- `runtime/turns.ts`: целочисленные коды `TurnKind` (`through 0, left 1, right 2, uturn 3, merge 4, diverge 5`)
  и биты масок. Коды стабильны, только дополняются.
- `rng.ts`: xoshiro128** + splitmix32; форки от мастера по сиду: `fork(0)` — спавн, `fork(1)` — водители,
  `fork(2)` — выбор манёвра при входе на линк и жребий нарушителя выделенки (остальные метки зарезервированы
  за пешеходами, маршрутизацией, автобусами).

## Порядок шага `step()` (dt = `config.dtS`)
0. **Часы.** `stepIndex++` в начале шага: всё, что шаг производит, относится к `t + dt`, и профиль часа, пиковые часы
   и времена поездок читают одно и то же время.
1. **Сигналы (T-09).** `SignalRuntime.computeStates(now)` заполняет `groupState` для всех групп сети (см.
   `runtime/signals.ts`), затем для каждого сигнализированного коннектора (`connSignalGroup[track] ≥ 0`)
   его состояние превращается в `entryBlockedCause`/`entryBlockedYellow`: `GREEN`/`FLASHING_GREEN` снимает
   блокировку; у `main`-групп `RED`/`RED_YELLOW` и у `arrow_*` всё, что не зелёное, ставят безусловную
   блокировку (`signal_red`/`arrow_off`); `YELLOW` у `main` ставит условную (`entryBlockedYellow = 1`) —
   решение конкретной машины принимается в шаге 6 (дилемма жёлтого). Несигнализированные коннекторы не
   трогаются (для T-11/T-15). 2. Пешеходы — T-15. 3. Маршрутизация — T-12.
4. **Выбор полосы (T-10).** Для каждой машины на полосе `LaneRuntime.targetLane` даёт обязательную целевую полосу
   (`pool.targetLane`, −1 = текущая подходит). Цель появляется в трёх случаях: манёвра нет с этой полосы
   (поворотная полоса, карман), полоса перестала допускать класс (выделенка в часы действия) или полоса
   заканчивается раньше линка. Манёвр (`pool.intendedTurn`) разыгрывается один раз при входе на линк —
   равномерно по движениям, которые линк предлагает классу, или по весам из `kernelOf(sim).setTurnShares(linkId, …)`
   (временная замена маршрутов T-12 и способ задавать поворотный спрос в тестах).
5. **Перестроения (MOBIL, T-10).** Два прохода, чтобы все решения читали одно состояние: (1) по полосам, обходя
   список от хвоста к голове с монотонными курсорами в списки соседних полос (новый лидер и новый последователь
   за O(1) амортизированно); (2) по индексам слотов — применение с перепроверкой зазоров, потому что две машины
   могли нацелиться в одну дыру. Обязательное перестроение смотрит только на соседа в сторону цели и добавляет
   `mandatoryBias`; дискреционное смотрит на обоих соседей, требует, чтобы соседняя полоса сохраняла нужный манёвр,
   и берёт лучший вариант; оно переоценивается раз в 5 шагов (0,5 с) со сдвигом по индексу слота. Соседство
   учитывает `[startS, endS]` (`lanesOverlapAt`): в карман можно войти только при `s ≥ startS`. Само перестроение
   мгновенно и сохраняет `s` и `geomSeg` (все полосы линка делят шкалу линка); длится 2 с — на это время
   поперечное смещение для рендера линейно интерполируется между осями полос и горит `BLINKER_LEFT/RIGHT`
   (пошаговые флаги, `persistentFlags` ядро по-прежнему не трогает). Одно перестроение в 2 с на машину.
6. **Ускорения** по схеме ARCHITECTURE §6: для каждой машины (по индексу слота) стартовое значение — свободный IDM,
   затем минимум по списку препятствий, и победившее препятствие становится `cause`. Препятствия сейчас:
   (а) лидер — `ahead[i]` или первая машина на следующих треках (`nextTrack` → `trackNextByClass`, до 3 треков
   или 250 м вперёд), причина `leader`; (б) стоп-линия в конце трека, если вход на `nextTrack` запрещён
   (`entryBlockedCause[nextTrack] ≠ 0`, неподвижное препятствие в `trackEndS`), причина — код из массива, —
   кроме случая жёлтого (`entryBlockedYellow[nextTrack] = 1`): если машина не может остановиться до стоп-линии
   при замедлении ≤ `comfortDecel · 1,5` (`mustStopAtYellow`), блокировка для неё в этом шаге снимается и она
   проезжает. Массив `entryBlockedCause` заполняют T-09/T-11/T-15, ядро его только читает. Препятствие считается
   причиной, если отнимает ≥ 0,1 м/с² относительно свободного ускорения; иначе `speed_limit` при `v ≥ 0,95·v0`,
   иначе `free_flow`. T-10 добавил ещё два препятствия: (в) **переполненный карман** — если целевая полоса это
   карман, машина ещё не доехала до его `startS`, а последняя машина кармана стоит ближе `startS + s0`, то
   препятствие в `startS`, причина `pocket_spillback` (машина стоит в своей полосе и держит поток за собой);
   (г) **конец полосы без продолжения** при незакрытом обязательном перестроении — препятствие в `trackEndS`,
   причина `lane_change_wait` (без него машина уехала бы за конец полосы и была бы сброшена; если менять полосу
   некуда, `targetLane = −1`, препятствия нет и машина по-прежнему сбрасывается). Наконец, машина, которая
   тормозит сильнее −0,5 м/с² с невыполненным **срочным** обязательным перестроением (то есть уже внутри
   `laneSelectionLookaheadM`, где `mandatoryBias > 0`), вместо `leader`/`free_flow`/`speed_limit`
   сообщает `lane_change_wait`. Каждое препятствие — вызов `accelTowardObstacle(i, v, v0, gap, vПрепятствия)`, без аллокаций.
   Ускорения считаются по состоянию начала шага, поэтому порядок обработки не влияет на траектории.
7. **Интеграция.** Полунеявный Эйлер: `v ← max(0, v + a·dt)`, `s ← s + v·dt`. Счётчик остановок при переходе `v`
   через `metrics.stoppedSpeedMps` вниз; флаги `BRAKING` (a < −0,3), `STOPPED`, `IN_INTERSECTION` (на коннекторе)
   объединяются с `persistentFlags`. Достигнув конца трека, машина переходит на `nextTrack` с переносом перебега
   (до 4 переходов за шаг). Если продолжения нет: на полосе с `trackIsExit` (конец линка в `gate`/`dead_end`)
   машина покидает сеть и поездка завершается; в остальных случаях (полоса кончается посреди линка, узел без
   разрешённого коннектора для класса) машина **сбрасывается**: счётчик `droppedVehicles` (через `kernelOf`),
   поездка не считается ни завершённой, ни активной. После T-10 обрыв полосы — это обязательное перестроение,
   поэтому на исправной сети `droppedVehicles` остаётся нулём; сброс означает, что уходить действительно некуда
   (единственная полоса без разрешённого коннектора для класса). Затем страховочная сортировка списков.
8. **Появление.** На каждых воротах пуассоновский процесс с интенсивностью
   `tripsPerHourPeak · hourlyProfile[h] · multiplier · gateShare`; при `tripsPerHourPeak = 0` —
   `0,7 · entryLaneCount · saturationFlowVehPerHPerLane`. Прибытия ждут в счётчике ворот, ограниченном
   `ceil(интенсивность ворот · 120 с)`; при снижении `demand.multiplier` через `setParams` накопленные прибытия
   обнуляются, поэтому множитель действует сразу даже за очередью. Прибытие входит, когда на одной из входных
   полос (наибольшее свободное место, при равенстве правая полоса) от начала свободно ≥ `length + driver.minGapM.max`.
   Класс `taxi` с вероятностью `taxiShare`, иначе `car`; тогда же разыгрывается флаг `BUS_LANE_VIOLATOR`
  (`behavior.busLaneViolatorShare`) и манёвр на первом линке. Скорость входа `min(v0, (gap − s0)/T)` — равновесие IDM
   при имеющемся зазоре. Прибытие, заставшее входную полосу занятой, один раз считается в `spawnWaits`
   (после прогрева); исчерпание бюджета машин в `spawnWaits` не входит.
9. Автобусы — T-14. 10. Метрики — T-18. 11. Инварианты — T-21.
12. Обновление `x/y/heading`, свёртка хеша траекторий.

Переход с полосы: машина берёт коннектор своего манёвра (`LaneRuntime.connectorFor`); если такого нет — первый
коннектор, ведущий на полосу, разрешённую её классу (`trackNextByClass`). Настоящие маршруты — T-12.

## Выходы
- `writeFrame(frame)`: первые `min(активных, capacity)` машин в порядке слотов; `signalStates` — реальные
  состояния групп (`SignalRuntime.groupState`, глобальный порядок), `crosswalkPeds` нулями (пешеходы — T-15).
- `tripStats()`: счётчики поездок, начавшихся после `demand.warmupMinutes`; `active` — текущее число машин класса
  в сети (все, включая появившиеся во время прогрева). Задержка поездки = время поездки − сумма
  `длина трека / (лимит трека × фактор водителя)` по пройденным трекам (не меньше нуля); `personDelayS` — задержка
  × наполненность класса на момент появления (пик/непик по `peakHours`).
- `writeMetrics()`: нулевые агрегаты правильной размерности. `report()`: `totals` из живого состояния
  (активные, завершённые, задержки завершённых поездок, средние скорости, доля стоящих), `items: []`.
- `setParams(patch)`: пути листьев патча сверяются с `RUNTIME_SAFE_PARAM_PATHS`, любой другой путь — исключение
  без побочных эффектов; допустимые применяются немедленно (`applyConfigPatch`).
- `kernelOf(sim)` — доступ к `RuntimeNetwork`, `VehiclePool`, `baseTripsPerHour`, `droppedVehicles`,
  `entryBlockedCause`, `entryBlockedYellow`, `signals` (`SignalRuntime`), `lanes` (`LaneRuntime`) и
  `setTurnShares(linkId, shares)` для тестов и отладки (не часть замороженной поверхности).
