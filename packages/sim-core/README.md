# @atl/sim-core

Чистая детерминированная микросимуляция движения: IDM (продольное), позже MOBIL, светофоры, перекрёстки,
маршруты, автобусы, пешеходы, метрики и детектор узких мест. Без DOM, Three, таймеров и `Math.random`.
Единственная точка входа: `createSimulation({ network, config, scenarioId })` → интерфейс `Simulation`
(`src/simulation.ts`, сигнатуры заморожены). Воркер, CLI и тесты используют только его.

Состояние после T-04: движение по полосам и коннекторам без перестроений, светофоров и конфликтов;
`writeMetrics` возвращает нули, `report` — только `totals` без `items`, `signalStates` в кадре заполнены `OFF`.

## Соглашения
- Координаты: `x` восток, `y` север, метры от центра bbox. Скорости м/с, ускорения м/с², время симуляции в секундах,
  время суток в минутах от полуночи. Курс в радианах против часовой стрелки от +x.
- **Трек** (track) — полоса или коннектор в одном индексном пространстве: полосы занимают `[0, laneCount)`,
  коннекторы `[laneCount, trackCount)`. Машина всегда ровно на одном треке.
- **`s` на полосе измеряется вдоль линка** (не вдоль полосы): все полосы одного линка делят шкалу, карман живёт
  в `[startS, endS]`, перестроение (T-10) сохраняет `s`. На коннекторе `s ∈ [0, lengthM]`.
- `s` — положение переднего бампера; машина занимает `[s − length, s]`. Зазор до лидера: `s_л − length_л − s`.

## Структуры данных

### `runtime/network.ts`: `RuntimeNetwork`
Плоское представление `Network` с целочисленными индексами; строится один раз, не меняется.
- Узлы: `nodeKind`, `nodeX/Y`. Линки: `linkFrom/To`, `linkLengthM`, `linkSpeedMps`, CSR-список полос `linkLanes`.
- Треки: `trackStartS/EndS`, `trackSpeedMps` (коннектор: минимум двух линков), `trackPoly` (индекс полилинии),
  `trackOffsetM` (боковое смещение полосы вправо от оси линка), `trackAllowedMask` (биты классов, см. `classBit`),
  `trackLink`, `trackNextByClass[track·4 + cls]` — следующий трек для класса или −1 (выход из сети).
- Полосы: `lanePos`, соседи `laneLeft/laneRight` (проверка пересечения по `s` — `lanesOverlapAt`),
  `laneReachesLinkEnd`, CSR-список выходных коннекторов `laneConnList`.
- Коннекторы: `connFromLane`, `connToLane`, `connViaNode`.
- Полилинии (линки, затем коннекторы) в одной таблице вершин `px/py/pcum` с направлением сегмента `segUx/segUy/segAngle`;
  `polyScale = длина полилинии / заявленная длина` переводит `s` в расстояние вдоль вершин. `locate(poly, d, hint)` ищет
  сегмент от кэшированного индекса. Положение машины на полосе = точка оси линка + `offset · правая нормаль`.
- Ворота: `gateShare` (доля спроса по `weightIn` среди ворот с входными полосами), CSR входных полос `gateLanes`
  (полосы с `startS = 0` входных линков), `entryLaneCount`.
- Сегменты метрик: полоса режется на `round(len / segmentLengthM)` равных кусков (`laneSegStart/Count/LengthM`);
  последний сегмент полосы, доходящей до конца линка, получает `approachNodeId`. Коннекторы сегментов не имеют.
- `signalGroupIds` (контроллеры в порядке сети, группы в порядке контроллера) и `crosswalkIds` — порядок для кадров.

### `runtime/vehicles.ts`: `VehiclePool`
Пул ёмкости `demand.vehicleBudget`, все массивы выделены в конструкторе; `step()` не аллоцирует.
- Идентичность и положение: `id` (стабильный, с 1, не переиспользуется), `track` (−1 = свободный слот), `nextTrack`,
  `s`, `v`, `a`, мировые `x/y/heading` (обновляются в конце шага), `geomSeg` (кэш сегмента полилинии).
- Машина и водитель: `cls`, `length`, `speedFactor` (желаемая скорость = лимит трека × фактор водителя × фактор класса),
  `timeHeadway`, `minGap`, `maxAccel`, `comfortDecel`, `politeness`, `laneChangeThreshold`, `gapLeftTurn`, `gapMerge`,
  `gapPedestrian`, `occupancy`. Все распределения сэмплируются при появлении в фиксированном порядке (`models/driver.ts`).
- Состояние: `flags` (`VehicleFlag`), `cause`, `rootCause`, `spawnTimeS`, `freeFlowTimeS`, `stops`, `countsInStats`.
- Списки по трекам: двусвязный список, упорядоченный по `s`: `trackHead` (самая дальняя машина), `trackTail`
  (ближайшая к началу), `ahead[i]` — лидер, `behind[i]` — последователь. Поиск лидера O(1); вставка от хвоста
  (`insert`), удаление (`remove`), страховочная сортировка вставками (`sortTrack`).
- Свободные слоты: LIFO-стек, `highWater` — верхняя граница занятых слотов, порядок обработки — по индексу слота.

### Прочее
- `runtime/clock.ts`: `simTimeS = stepIndex · dtS` (без дрейфа), `timeOfDayMin = (startTimeMin + simTimeS/60) mod 1440`.
- `runtime/trajectory-hash.ts`: FNV-1a по `(id, round(x·100), round(y·100), round(v·100))` каждой машины, суммы за шаг
  (независимо от порядка) сворачиваются в два 32-битных аккумулятора на каждом шаге → 16 hex-символов.
- `models/idm.ts`: `a = a_max·[1 − (v/v0)⁴ − (s*/gap)²]`, `s* = s0 + max(0, v·T + v·Δv / (2√(a_max·b)))`.
- `rng.ts`: xoshiro128** + splitmix32; форки от мастера по сиду: `fork(0)` — спавн, `fork(1)` — водители
  (остальные метки зарезервированы за пешеходами, маршрутизацией, автобусами).

## Порядок шага `step()` (dt = `config.dtS`)
1. Сигналы — T-09. 2. Пешеходы — T-15. 3. Маршрутизация — T-12. 4. Выбор полосы — T-10. 5. Перестроения — T-10.
6. **Ускорения.** Для каждой машины по индексу слота: лидер = `ahead[i]`; если его нет — первая машина на следующих
   треках (`nextTrack` → `trackNextByClass`, до 3 треков или 250 м вперёд). Ускорение = IDM. `cause`:
   `leader`, если лидер отнимает ≥ 0,1 м/с² относительно свободного ускорения; иначе `speed_limit` при `v ≥ 0,95·v0`;
   иначе `free_flow`. Ускорения считаются по состоянию начала шага, поэтому порядок обработки не влияет на траектории.
7. **Интеграция.** Полунеявный Эйлер: `v ← max(0, v + a·dt)`, `s ← s + v·dt`. Счётчик остановок при переходе `v`
   через `metrics.stoppedSpeedMps` вниз; флаги `BRAKING` (a < −0,3), `STOPPED`, `IN_INTERSECTION` (на коннекторе).
   Достигнув конца трека, машина переходит на `nextTrack` с переносом перебега (до 4 переходов за шаг) или,
   если следующего трека нет, покидает сеть (поездка завершается). Затем страховочная сортировка списков.
8. **Появление.** На каждых воротах пуассоновский процесс с интенсивностью
   `tripsPerHourPeak · hourlyProfile[h] · multiplier · gateShare`; при `tripsPerHourPeak = 0` —
   `0,7 · entryLaneCount · saturationFlowVehPerHPerLane`. Прибытия ждут в счётчике ворот и входят, когда на одной
   из входных полос (выбирается полоса с наибольшим свободным местом) от начала свободно ≥ `length + driver.minGapM.max`.
   Класс `taxi` с вероятностью `taxiShare`, иначе `car`. Скорость входа `min(v0, (gap − s0)/T)` — равновесие IDM
   при имеющемся зазоре. Прибытие, заставшее входную полосу занятой, один раз считается в `spawnWaits`
   (после прогрева); исчерпание бюджета машин в `spawnWaits` не входит.
9. Автобусы — T-14. 10. Метрики — T-18. 11. Инварианты — T-21.
12. Обновление `x/y/heading`, свёртка хеша траекторий, `stepIndex++`.

Переход с полосы: машина берёт **первый** коннектор из `network.connectors`, ведущий на полосу, разрешённую её классу
(временная замена маршрутов T-12). Полоса без разрешённых коннекторов (ворота, тупик, полоса, заканчивающаяся
посреди линка) — выход из сети.

## Выходы
- `writeFrame(frame)`: первые `min(активных, capacity)` машин в порядке слотов; `signalStates` заполнены `OFF`
  (сигналы не считаются до T-09), `crosswalkPeds` нулями.
- `tripStats()`: счётчики поездок, начавшихся после `demand.warmupMinutes`; `active` — текущее число машин класса
  в сети (все, включая появившиеся во время прогрева). Задержка поездки = время поездки − сумма
  `длина трека / (лимит трека × фактор водителя)` по пройденным трекам (не меньше нуля); `personDelayS` — задержка
  × наполненность класса на момент появления (пик/непик по `peakHours`).
- `writeMetrics()`: нулевые агрегаты правильной размерности. `report()`: `totals` из живого состояния
  (активные, завершённые, задержки завершённых поездок, средние скорости, доля стоящих), `items: []`.
- `setParams(patch)`: пути листьев патча сверяются с `RUNTIME_SAFE_PARAM_PATHS`, любой другой путь — исключение
  без побочных эффектов; допустимые применяются немедленно (`applyConfigPatch`).
- `kernelOf(sim)` — доступ к `RuntimeNetwork`, `VehiclePool` и `baseTripsPerHour` для тестов и отладки
  (не часть замороженной поверхности).
